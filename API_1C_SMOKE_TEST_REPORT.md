### 5. `POST .../orders/createOrder`

Проверено несколько сценариев.

| Сценарий | HTTP | Результат |
|----------|------|-----------|
| Как в руководстве: `customer_id` = `НФ-000580`, `product_id` = `НФ-00001137`, `warehouse_id` = `MAIN` | **200** | `status`: `accepted`, `reserved`: `true` |
| Тот же клиент `НФ-000580`, другой товар `НФ-00004612`, `warehouse_id` = `MAIN` | **200** | заказ принят |
| Клиент `НФ-000238`, товар `НФ-00004612`, `warehouse_id` = `MAIN` | **500** | Ошибка платформы 1С (см. ниже) |
| Запрос без `warehouse_id` (клиент `НФ-000238`) | **500** | Та же типовая ошибка модуля |

Текст ошибки 500 (фрагмент):

```text
Неверный первый параметр Ссылка в функции ОбщегоНазначения.ЗначенияРеквизитовОбъекта:
Значение должно быть ссылкой или именем предопределенного элемента
```

**Вывод:**

- Эндпоинт **работает**, если в заказе указаны **существующие** в базе и **корректные для обработки** контрагент и номенклатура (как в примере руководства).
- Для контрагента `НФ-000238` при том же формате запроса сервер возвращает **500** — это **не сетевая** и не **авторизационная** проблема, а **ошибка/данные на стороне конфигурации 1С** (некорректная или неподходящая ссылка при разборе объекта).

**Что сделать, чтобы исправить сценарий с «плохим» контрагентом:**

1. В конфигурации 1С проверить элемент справочника контрагента с кодом/идентификатором, который передаётся в `customer_id` (в тесте — `НФ-000238`): заполнение обязательных реквизитов, тип контрагента, договоры, блокировки.
2. Проверить код HTTP-сервиса создания заказа: вызов `ЗначенияРеквизитовОбъекта` — не передаётся ли туда пустая или нессылочная переменная для части контрагентов.
3. В руководстве для интеграторов явно указать: при **424 NOT_FOUND** — нет объекта; при **500** с текстом про «Ссылка» — обращаться к администратору 1С с номером контрагента и телом запроса.

## HTTPS / сертификат

При запросе **без** отключения проверки сертификата (`curl` без `-k`):

```text
SSL certificate problem: self signed certificate
```

**Что сделать:**

- Для production: выпустить сертификат от доверенного ЦС (Let’s Encrypt и т.д.) или установить корпоративный корневой сертификат на серверах, которые ходят в API.
- Для локальной отладки: временно `curl -k` или настройка доверия к конкретному сертификату — только осознанно.
